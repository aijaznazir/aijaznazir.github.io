Linear algebra · Chapter 6 of 7

Range and kernel: what comes out, what gets lost

Every linear transformation has a set of outputs it can reach and a set of inputs it destroys. Those two spaces, and the two that come with them, organize everything about solving Ax = b.

Two questions about any transformation

Take a linear transformation \(T : \mathbb R^n \to \mathbb R^m\). It eats vectors with \(n\) entries and returns vectors with \(m\) entries. Two questions describe it almost completely.

What can come out? The set of all outputs is the range of \(T\):

$$\mathcal R(T) = \{\, T(\vec x) : \vec x \in \mathbb R^n \,\} \;\subseteq\; \mathbb R^m .$$

What gets lost? The set of inputs sent to the zero vector is the kernel of \(T\):

$$\ker(T) = \{\, \vec x \in \mathbb R^n : T(\vec x) = \vec 0 \,\} \;\subseteq\; \mathbb R^n .$$

Keep track of where each one lives. The kernel is a set of inputs, so it sits in \(\mathbb R^n\). The range is a set of outputs, so it sits in \(\mathbb R^m\). When \(n \neq m\) they are not even in the same space, which is why the visualizer below draws input space and output space separately.

The same two spaces, with matrix names

Every linear \(T\) is multiplication by its standard matrix, whose columns are where the basis vectors land (chapter 2): \(A = [\,T(\vec e_1)\;\cdots\;T(\vec e_n)\,]\). Chapter 2's column picture says

$$A\vec x = x_1\vec a_1 + x_2\vec a_2 + \cdots + x_n\vec a_n ,$$

so the outputs are exactly the linear combinations of the columns. That set has its own name, the column space \(\operatorname{Col}(A) = \operatorname{span}\{\vec a_1, \ldots, \vec a_n\}\). The inputs with \(A\vec x = \vec 0\) form the null space \(\operatorname{Nul}(A)\). Hence

$$\mathcal R(T) = \operatorname{Col}(A), \qquad \ker(T) = \operatorname{Nul}(A).$$

So the four names describe two spaces. "Range" and "kernel" are what you say when thinking of the function \(T\); "column space" and "null space" are what you say when holding the matrix \(A\).

Both are subspaces: they contain \(\vec 0\) and are closed under adding and scaling. For the kernel, if \(A\vec x = \vec 0\) and \(A\vec y = \vec 0\) then \(A(\vec x + \vec y) = \vec 0\) and \(A(c\vec x) = \vec 0\). For the range, \(A\vec x + A\vec y = A(\vec x + \vec y)\) and \(cA\vec x = A(c\vec x)\) are outputs again. In \(\mathbb R^2\) and \(\mathbb R^3\) the subspaces come in only four shapes: the origin alone, a line through the origin, a plane through the origin, or the whole space.

One-to-one and onto

\(T\) is onto when every vector of \(\mathbb R^m\) is an output: \(\mathcal R(T) = \mathbb R^m\). It is one-to-one when different inputs always give different outputs. The kernel decides the second property completely: if \(A\vec x = A\vec y\) then \(A(\vec x - \vec y) = \vec 0\), so two inputs share an output exactly when they differ by a kernel vector. Therefore

$$T \text{ is one-to-one} \iff \ker(T) = \{\vec 0\}.$$

More than that, every output that is reached is reached by a whole copy of the kernel, shifted to pass through one solution (the picture from chapter 5). A big kernel means many inputs are squeezed onto each output.

Finding bases by row reduction

Row operations replace equations by equivalent ones, and each operation can be undone, so \(A\vec x = \vec 0\) and \(R\vec x = \vec 0\) have exactly the same solutions, where \(R = \operatorname{rref}(A)\). Both procedures rest on that one fact.

Null space. Solve \(R\vec x = \vec 0\). Each column without a pivot gives a free variable; the pivot variables are then determined by the free ones. Writing the general solution as a combination of the free variables gives one basis vector per free variable. They are independent because each has a 1 in its own free position where all the others have 0.

Column space. Take the pivot columns of the original \(A\). The reason: since \(A\vec x = \vec 0 \iff R\vec x = \vec 0\), every linear relation among the columns of \(A\) holds among the columns of \(R\) with the same coefficients, and vice versa. In \(R\) the pivot columns are clearly independent and every other column is a combination of them, so the same is true for the matching columns of \(A\). Using columns of \(R\) instead is a real mistake, not a matter of taste: for

$$A = \begin{bmatrix} 1 & 2 \\ 2 & 4 \end{bmatrix}, \qquad R = \begin{bmatrix} 1 & 2 \\ 0 & 0 \end{bmatrix},$$

\(\operatorname{Col}(R)\) is the \(x\)-axis, while \(\operatorname{Col}(A)\) is the line through \((1, 2)\). Row operations recombine the rows, which changes the output coordinates and therefore the column space itself; what they preserve is the pattern of dependencies among the columns.

Rank–nullity

Count columns. Each of the \(n\) columns of \(R\) either has a pivot, contributing one basis vector to \(\operatorname{Col}(A)\), or is free, contributing one basis vector to \(\operatorname{Nul}(A)\). So

$$\operatorname{rank}(A) + \operatorname{nullity}(A) = n,$$

where the rank is the dimension of the column space and the nullity is the dimension of the null space. Read through the transformation: the dimensions that survive plus the dimensions that are crushed add up to the dimension you started with. It also gives quick tests: \(T\) is onto exactly when \(\operatorname{rank}(A) = m\) (a pivot in every row) and one-to-one exactly when \(\operatorname{rank}(A) = n\) (a pivot in every column).

Each row can be checked in the visualizer, and each follows the same two steps. Take the map \(T(x_1,x_2,x_3) = (x_1 - x_3,\; 3x_1 + x_2 + 5x_3)\). Applying \(T\) to \(\vec e_1, \vec e_2, \vec e_3\) gives the columns of

$$A = \begin{bmatrix} 1 & 0 & -1 \\ 3 & 1 & 5 \end{bmatrix} \;\sim\; \begin{bmatrix} 1 & 0 & -1 \\ 0 & 1 & 8 \end{bmatrix} = R.$$

Both rows have pivots, so the rank is \(2 = m\): the range is all of \(\mathbb R^2\) and \(T\) is onto. Column 3 is free, so \(x_3 = t\), \(x_1 = t\), \(x_2 = -8t\), and the kernel is the line spanned by \((1, -8, 1)\). With \(n = 3\) inputs, rank–nullity reads \(2 + 1 = 3\). A map from \(\mathbb R^3\) to \(\mathbb R^2\) can never be one-to-one: its kernel has dimension at least \(3 - 2 = 1\).

The four fundamental subspaces

The phrase "four fundamental subspaces" usually means four genuinely different spaces, following Gilbert Strang. The column space and null space are two of them. The other two come from looking at the rows of \(A\), which is the same as looking at the columns of \(A^{T}\):

SubspaceLives inDimensionBasis from row reduction
Column space \(\operatorname{Col}(A) = \mathcal R(T)\)\(\mathbb R^m\)\(r\)pivot columns of \(A\)
Null space \(\operatorname{Nul}(A) = \ker T\)\(\mathbb R^n\)\(n - r\)one vector per free variable
Row space \(\operatorname{Row}(A) = \operatorname{Col}(A^{T})\)\(\mathbb R^n\)\(r\)nonzero rows of \(\operatorname{rref}(A)\)
Left null space \(\operatorname{Nul}(A^{T})\)\(\mathbb R^m\)\(m - r\)null space of \(A^{T}\)

Here \(r\) is the rank. The row space keeps the basis from \(\operatorname{rref}(A)\) because row operations only form combinations of rows and can be undone, so they never change the span of the rows. That also shows the row space has dimension \(r\): "row rank equals column rank". The left null space is named for the equation it solves, \(\vec y^{T}\!A = \vec 0^{T}\), with \(\vec y\) multiplying from the left.

They come in perpendicular pairs

Write out \(A\vec x = \vec 0\) one row at a time. Each entry says (row \(i\) of \(A\)) \(\cdot\, \vec x = 0\). So a null-space vector is perpendicular to every row, and therefore to every combination of rows:

$$\operatorname{Nul}(A) \perp \operatorname{Row}(A) \ \text{in } \mathbb R^n, \qquad \operatorname{Nul}(A^{T}) \perp \operatorname{Col}(A) \ \text{in } \mathbb R^m .$$

The dimensions \(r\) and \(n - r\) add up to \(n\), so the two perpendicular subspaces together fill \(\mathbb R^n\): every input splits uniquely as \(\vec x = \vec x_{\text{row}} + \vec x_{\text{null}}\). The same holds in \(\mathbb R^m\) for the column space and left null space.

What A does with each piece

Since \(A\vec x_{\text{null}} = \vec 0\),

$$A\vec x = A\vec x_{\text{row}} + A\vec x_{\text{null}} = A\vec x_{\text{row}} .$$

The null-space part is simply erased, and the row space carries everything that survives. In fact \(A\) maps \(\operatorname{Row}(A)\) one-to-one onto \(\operatorname{Col}(A)\): two row-space vectors with the same image would differ by a vector lying in both the row space and the null space, and only \(\vec 0\) is perpendicular to itself. In the output space, any target splits as \(\vec b = \vec b_{\text{col}} + \vec b_{\text{left}}\), and \(A\vec x = \vec b\) can be solved exactly when \(\vec b_{\text{left}} = \vec 0\). The visualizer draws both splits: dashed lime and magenta pieces of \(\vec x\) on the left, and the dashed orange left-null piece of \(\vec b\) on the right.

About the explorer. Row reduction is done in exact fractions, so the bases shown are the same ones MATLAB's null(A,'r') and the pivot columns from rref return. The drawings use the same bases, and the splits \(\vec x_{\text{row}} + \vec x_{\text{null}}\) and \(\vec b_{\text{col}} + \vec b_{\text{left}}\) are orthogonal projections. Inputs from \(\mathbb R^4\) cannot be drawn, so for 3×4 matrices the input side shows numbers only.
